Squat Runtime

This page documents the smallest runnable counting surface in the repo. It packages the squat-only branch into one runtime: optional YOLO pose extraction, engineered squat features, and the dedicated squat TCN, with FSM retained as a transparent fallback/reference path.

Why This Exists

Scope

runnable locally offline prototype not the full routed system

The broader project ended with an exercise-dependent route map. This runtime does not try to hide that. It exposes only the squat path because that is the cleanest branch to package locally from the repo artifacts, and it now defaults to the saved squat TCN checkpoint.

Why keep FSM at all

The dedicated squat TCN is the right default because its full local run directory is now available. The FSM is still kept because it is transparent, easy to debug, and useful as a fallback/reference path when you want event-frame style diagnostics.

Input Modes

--video-path

Runs YOLO pose extraction first, then builds squat features and counts repetitions.

slowest needs OpenCV + Ultralytics

--pose-path

Starts from an existing pose array shaped like the project pose features: [T, 51].

middle path reuses extracted pose

--feature-path

Starts from an existing engineered squat-feature array and runs the selected squat backend directly.

fastest best smoke-test mode

How To Run

From a video

source .venv/bin/activate
python3 CV_Image_pose_detection/artifacts/3_Modeling/run_squat_counter.py \
  --video-path CV_Image_pose_detection/Data/LLSP/video/valid/train3946.mp4 \
  --output-json CV_Image_pose_detection/artifacts/3_Modeling/training_outputs/train3946_squat_runtime.json \
  --pretty

From saved squat features with the default TCN backend

source .venv/bin/activate
python3 CV_Image_pose_detection/artifacts/3_Modeling/run_squat_counter.py \
  --feature-path CV_Image_pose_detection/Data/LLSP/annotation_cleaned/squat_features/train3946_squat_features.npy \
  --pretty

Force the FSM reference path

source .venv/bin/activate
python3 CV_Image_pose_detection/artifacts/3_Modeling/run_squat_counter.py \
  --feature-path CV_Image_pose_detection/Data/LLSP/annotation_cleaned/squat_features/train3946_squat_features.npy \
  --counter-backend fsm \
  --pretty

What It Returns

Output JSON fields

  • prediction.pred_count: primary squat rep estimate for the selected backend
  • prediction.raw_pred_count: continuous TCN count before rounding when TCN is used
  • reference_predictions.fsm.event_frames: detected rep-completion frames in the engineered sequence
  • reference_predictions.fsm.mean_conf: lower-body pose confidence summary
  • backend_selection: whether the runtime used the TCN directly or fell back to FSM
  • video_metadata: fps, frame count, and duration when a video input is used

Interpretation

This runtime should be presented as a squat-only research prototype. A practical expectation around ±1 to ±2 reps is defensible on typical clips, but hard cases can still fail because of framing, target ambiguity, or borderline repetition definitions.

Known Limits

  • It does not perform exercise recognition; the input is assumed to be a squat clip.
  • It does not expose the full routed system in one command.
  • The runtime is still squat-only even though it now defaults to the stronger saved squat TCN.
  • It is an offline prototype, not a production webcam or mobile application.
