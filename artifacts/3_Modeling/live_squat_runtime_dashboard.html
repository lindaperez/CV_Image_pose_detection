Live Squat Counter

This page documents the live squat-only prototype: webcam input, frame-wise YOLO pose, tracked target selection, accumulated squat feature buffer, live TCN inference, and on-screen count display. It uses the same saved squat TCN as the offline runtime.

How It Works

Pipeline

  • Read frames from a webcam.
  • Run YOLO pose on each frame with tracked-person selection.
  • Append detected pose frames to the current session buffer.
  • Rebuild squat features from the session buffer every few frames.
  • Run the saved squat TCN and display a stabilized count.

What is shown on screen

  • Current displayed squat count.
  • Raw and smoothed TCN prediction.
  • Tracked pose overlay and bounding box.
  • Detected pose frames, preview FPS, and session duration.
  • Tracking status, recording status, and active run name.

Run It

Default webcam run

source .venv/bin/activate
python3 CV_Image_pose_detection/artifacts/3_Modeling/run_live_squat_counter.py \
  --mirror \
  --tcn-device cpu

Choose a different camera or model device

source .venv/bin/activate
python3 CV_Image_pose_detection/artifacts/3_Modeling/run_live_squat_counter.py \
  --camera-index 1 \
  --device mps \
  --tcn-device mps \
  --mirror

Start recording immediately on launch

source .venv/bin/activate
python3 CV_Image_pose_detection/artifacts/3_Modeling/run_live_squat_counter.py \
  --mirror \
  --tcn-device cpu \
  --auto-record

Controls

Live controls

  • Ctrl+S: start recording the displayed live overlay to an .mp4
  • e: stop recording and save the current video
  • --auto-record: begin recording immediately at launch without waiting for a keypress
  • r: reset the live session buffer and count
  • q: quit the live window

Saved recordings

Unless you override --recording-dir, the videos are written under artifacts/3_Modeling/training_outputs/live_squat_recordings.

Important Limits

What this is good for

A local demonstration that the saved squat pose model can be turned into an interactive prototype, not just an offline notebook result.

What this is not

It is not a production workout app. The live count is estimated from the accumulated session buffer, so framing problems, target switching, and borderline reps can still produce unstable or wrong counts.
